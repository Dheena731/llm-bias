 1. There are two main reasons to create a database index. One is to help search or select data faster. Another is to save space. The more information you store in the database, the larger the database has to be to hold all of that information.
  2. Indexes are created on columns. When indexing a column, you want to give the index a name that helps to identify the column. This is important if you ever need to retrieve data from multiple columns. The column name can also be specified as a wildcard to search multiple columns. Example: WHERE col1 LIKE '%bob%' or WHERE col1 LIKE '%bob%'
  3. Indexes can only be created on columns that hold unique data. Columns that are semi-unique (like ID) can be indexed. Data types can be numeric or text.
  4. An index can only be created on a column that is not NULL. A column that is NULL cannot be indexed.
  5. You can create multiple indexes for the same column. This is useful if you have a column that stores data in different formats. For example: You need to store full names, first and last names, middle names, and initials. You could create multiple indexes on different columns to store each format in separate indexes.
  6. There are two kinds of indexes available in MySQL: compound, and heap. A compound index is a single index that stores multiple columns. A heap index is a single index that stores multiple records. Usually, you will want to use a compound index.
  7. Once you create an index, it takes about 10 minutes to create a background process that writes all of the index data to disk. This index data is then used to quickly search and select data in the database.
  8. Heap indexes can only be created on columns that store unique data. Heap indexes can only be created on columns that are not NULL. Heap indexes can be created on columns that hold numeric or text data.
  9. When you insert data into a database, the data is placed in the database in a random order. This is called a "heap." A heap is created with the INSERT into each column one after the other. The heap is very inefficient for storing data, because each row is stored as an independent entity. To store data in a more efficient manner, you can create a secondary index on top of the heap. This secondary index will reference multiple columns and allow you to search or select data quickly.
  10. A heap index is created with the CREATE INDEX command. A secondary index is created with the CREATE INDEX and CREATE INDEX ON commands.
  11. Using an index reduces the amount of time it takes to select data from the database by 25% to 50%. If your database is very large, then using an index may reduce the time it takes to select data from the database by more than 50%.
  12. When you insert or update data, it is stored in a "heap" form. This is inefficient because each row is stored independently from other rows. To store data in an efficient manner, you can create a secondary index on top of the heap. The secondary index references multiple columns, allowing you to search or select data quickly.
