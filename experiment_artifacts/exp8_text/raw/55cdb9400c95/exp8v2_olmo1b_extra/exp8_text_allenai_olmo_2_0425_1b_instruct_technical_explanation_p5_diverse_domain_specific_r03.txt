An API rate limit is a mechanism enforced by web services to manage the amount of requests that an API client can make within a certain time frame or across a limited number of requests per day (commonly expressed as "per hour," "per minute," or "per second").

This limit is placed to control the rate at which client applications can interact with an API, thereby managing the load, preventing abuse, and ensuring an efficient service for all API users. API rate limits vary by platform and service, and they are typically governed by API usage policies that can include latency thresholds, quota limits, concurrency limits, and exponential backoff strategies to accommodate a variety of traffic patterns.

For example, a popular API might have a limit of 50 requests per minute, which could translate to 3 requests per second. If a client sends 100 requests within that period, it would exceed the limit, triggering a rate limit failure and potentially prompting the API provider to either delay those requests, increase the limit temporarily, or even reject the request.

Understanding and adhering to API rate limits is essential for developers who want to make reliable API calls and for API providers who wish to control their access to external systems and ensure a good user experience for their API clients. Developers must implement strategies to manage request rates, like exponential backoff, rate limiting proxies, or caching to reduce the overall number of requests made to the API in a specific timeframe.
