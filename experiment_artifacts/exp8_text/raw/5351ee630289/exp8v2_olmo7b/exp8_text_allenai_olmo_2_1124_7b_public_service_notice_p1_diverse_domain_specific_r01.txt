In this sub-unit of the "Language Syntax" chapter, we will cover grammar rules. Grammars are sets of rules that define how to form valid sentences in a language. They can be used, for example, by compilers to check whether programs are valid or not. A simple grammar rule might say that a number must consist of digits only, so that 123 would be valid but foo would not.

Grammars can be specified in different ways, such on the form of productions, which describe how to build up valid sentences from smaller ones. For instance, a simple grammar rule with two nonterminals N and M could state that N -> aMb (i.e., an N consists of an a followed by an M followed by a b). This means that N can be replaced by aMb in strings that contain an N.

A common type of language specification is called a context-free grammar (CFG), which describes all possible structures in terms of terminals and nonterminals combined using productions. For example, the CFG for arithmetic expressions consists of the following:

Variables: E = x | y | z

Constants: + - * /

Arithmetic operators: ( , )

Expressions: E -> E + E | E * E | E / E | (E) | var | E ^ E | int

Rules like these allow us to generate string trees representing valid expressions. Here is an example of a simple expression tree generated by the above CFG:

Var : x

Expr : Var + Var

Tree : [x, x] + [x, x]

Traversing this tree from its root node (the leftmost node) down to any leaf node (the outermost nodes) yields the string x + x + x or simply 3*x.

A grammar can also specify a hierarchy among its rules, allowing for more complex structures than the simple CFG described above. For instance, a production might contain several alternatives, such as N -> A | B | C, meaning that N stands for either A, B, or C.
