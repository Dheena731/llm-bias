Write in first person, present tense, and be casual. For example, use "I will" instead of "This job needs".

The flowcharts are intended to be simple - if they are too complicated, they are probably not the right tool for this project.

Please limit the number of flowcharts to about 20. Keep in mind that each flowchart will need to be reviewed by multiple people in order to be usable.

The flowcharts should focus only on the most important decisions - there will be an opportunity to add details when the flowcharts are used.

The flowcharts are intended to be used by people who understand the system, and that's okay. They are also intended to help the development team quickly understand where they need to get additional context or clarifications.

If a flowchart shows a dependent decision, the decision should be made earlier in the flowchart. For example, if the decision is "do you have a membership?" and the next decision is "do you want to pay your monthly expense?" then the "pay monthly expense" should be the previous decision.

If a decision is mandatory, make sure that the flowchart goes to the error state when the decision is not met.

In order to keep the number of flowcharts reasonable, try not to add more than one decision to each step in the flowchart.

When adding a decision to a flowchart, add a description of the decision in the comments section. The description should be short and to the point, and should be written in plain English.
