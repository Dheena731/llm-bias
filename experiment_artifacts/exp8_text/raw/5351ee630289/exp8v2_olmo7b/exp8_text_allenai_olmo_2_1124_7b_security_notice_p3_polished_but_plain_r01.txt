The title

The title should be meaningful and concise, and is a short sentence, typically < 2 items:

  • The goal of the message: for example, “Remote work; VPN fallback” or “Internal Parking Lot; update”.
  • The category the message is coming from: for example, “Operations”, “Software Engineering”, or “Human Resources”.

Use multiple-line titles, not one-line titles.

The content

The content should be clear and concise, and try to answer the following questions:

  • What is it? (purpose)
  • When is it? (timing)
  • Where is it? (location)
  • Why is it? (rationale)
  • How is it? (details)

Use multiple-line content, not one-line content.

If the message is a reminder, then it should contain an actionable item to do.

If the message is a notification, then it should contain an actionable item to read. It should include a simple call to action, such
as “Read more here: …” or “Read more here: … URL”.

If the message is a request, then it should contain an actionable item to
answer or reply.

There should be a single call to action.

Avoid requests that have no clear action to take. The recipient may feel that
they need to take action, but don’t know how to take that action. Avoid
vague or broad requests like “Email me”, “Call me”, “Confirm”, “Let me know”,
“Update me”, “Let me know your thoughts on…” unless there is a clear
expectation or intention for what that means, and the recipient has that

If it contains a link, then the link needs to be self-contained, which means
that it needs to be able to work without any dependencies, and that the
message should not contain any text that explains what to do with the link.
If the recipient needs an explanation, they can read the message body, and
then follow the link if they need more information.

If it contains an emoji, then it should be a very common emoji or a
consistent emoji.

If it contains a link, then it should not contain a trailer text or
decoration. The recipient should not need to parse any text that comes
before or after the link to understand what to do with it.

If it contains a link, then it should not contain an expectation that the
recipient needs to download something, open a browser, scroll down, type in
a password, click OK, and so on. If it needs to be downloaded, then make it
clear that it needs to be downloaded. If it needs to be run, then make it
clear that it needs to be run.

If it contains a link, then it should not be a link that makes the recipient
log into a service.

If it contains a link, then it should be a link that is not generated by
another email. If it’s generated by another email, then it should include
the complete URL in the email body.
