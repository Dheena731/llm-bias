An API rate limit is a restriction on how many requests a client can make to an API within a specific period of time. For example, a service might allow 100 requests per minute or 10,000 requests per day from a single API key or IP address. Once the limit is reached, further requests are typically rejected until the time window resets, often with an HTTP 429 "Too Many Requests" error.

Providers use rate limits to protect their servers from overload, ensure fair access among users, control costs, and prevent abuse such as scraping or denial-of-service attacks. Developers handle rate limits by checking response headers that report remaining quota and reset times, caching results, batching requests, and retrying with exponential backoff.
