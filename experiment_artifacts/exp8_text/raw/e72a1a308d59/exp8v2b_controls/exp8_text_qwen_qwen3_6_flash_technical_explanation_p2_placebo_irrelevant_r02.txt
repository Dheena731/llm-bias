A database index is a supporting data structure that dramatically speeds up data retrieval from a table. Without an index, the database must perform a sequential scan, inspecting every row until it finds a match. An index works much like the index at the back of a textbook: instead of reading cover-to-cover, you look up a term and are pointed directly to the relevant pages. Technically, it maintains a sorted map of column values to the physical disk locations of those rows, enabling the query engine to use fast lookup algorithms (typically tree-based structures like B-trees) rather than linear searches.

Indexes improve read performance but introduce trade-offs. They consume additional storage space and slow down write operations (INSERT, UPDATE, DELETE) because the database must maintain the index alongside the actual data. For this reason, indexes are usually created selectively on columns that appear frequently in `WHERE`, `JOIN`, or `ORDER BY` clauses. When applied judiciously, they are one of the most effective tools for keeping database queries responsive.
