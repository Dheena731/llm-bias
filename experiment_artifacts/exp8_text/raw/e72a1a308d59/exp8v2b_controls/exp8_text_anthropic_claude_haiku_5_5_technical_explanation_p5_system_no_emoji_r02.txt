An API rate limit is a restriction on how many requests a client can send to an API within a specific time period, such as 100 requests per minute or 10,000 requests per day. When a client exceeds this limit, the server typically rejects further requests, often with an HTTP 429 "Too Many Requests" status code, until the window resets.

Providers use rate limits to protect their servers from overload, ensure fair access among users, prevent abuse such as scraping or denial-of-service attacks, and manage costs. Limits may apply per API key, per user, per IP address, or per endpoint. Clients can handle them gracefully by monitoring response headers that show remaining quota and reset times, and by retrying with exponential backoff.
