An API rate limit is a restriction on how many requests a client can send to an API within a specific time period, such as 100 requests per minute or 10,000 requests per day. Providers set these limits to protect their servers from overload, ensure fair access among many users, control costs, and prevent abuse such as denial-of-service attacks or scraping.

When a client exceeds its limit, the API typically rejects further requests, often returning an HTTP 429 "Too Many Requests" status code, sometimes along with a header indicating when the client can try again. Developers handle rate limits by monitoring their request volume, caching responses, batching requests where possible, and retrying with exponential backoff when they hit the limit.
