An API rate limit is a cap on how many requests a client (such as an app, script, or user account) can send to an API within a set period of time. For example, a service might allow 100 requests per minute or 10,000 per day.

**Why they exist**
- **Protecting the service:** Limits keep a server from being overwhelmed by too much traffic, whether from a bug, a poorly written program, or a deliberate attack.
- **Fair use:** They stop any single client from using more than its share, so everyone gets reasonable performance.
- **Cost control and business terms:** Providers often set higher limits for paying customers than for free users.

**What happens when you exceed the limit**
The API typically rejects further requests until the time period resets. Most APIs do this by returning an HTTP status code of 429, which means "Too Many Requests." The response often includes information about how long to wait before trying again.

**How to work within a rate limit**
- Check the API's documentation to learn its limits.
- Slow down or space out your requests.
- Cache results you've already received instead of requesting them again.
- When you receive a 429 response, wait before retrying, and increase the wait each time it happens again.

In short, a rate limit is a rule that controls how often you can call an API, and staying within it keeps both your application and the service working reliably.
