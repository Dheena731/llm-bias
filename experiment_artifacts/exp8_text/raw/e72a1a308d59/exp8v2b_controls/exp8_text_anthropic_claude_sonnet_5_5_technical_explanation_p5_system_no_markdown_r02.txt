An API rate limit is a cap on how many requests a client can make to an API within a certain period of time, such as 100 requests per minute or 10,000 requests per day. Providers set these limits to protect their servers from being overloaded, to keep usage fair across all customers, to prevent abuse or attacks, and to control infrastructure costs.

When you exceed the limit, the API typically rejects further requests until the time window resets. The most common response is an HTTP 429 status code ("Too Many Requests"), often accompanied by headers that tell you how many requests you have left or how long to wait before trying again, such as Retry-After.

To work within rate limits, developers commonly cache responses, batch requests where possible, spread calls out over time, and use exponential backoff, which means waiting progressively longer between retries after a failure. Many providers also offer higher limits through paid plans or special arrangements.
