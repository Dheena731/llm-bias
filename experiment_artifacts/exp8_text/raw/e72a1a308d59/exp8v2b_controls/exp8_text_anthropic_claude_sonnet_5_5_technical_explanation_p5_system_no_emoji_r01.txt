An API rate limit is a cap on how many requests a client can send to an API within a set period of time, such as 100 requests per minute or 10,000 per day. Providers use rate limits to protect their servers from being overwhelmed, to keep service fair and available for all users, and to prevent abuse or accidental overuse.

When a client exceeds the limit, the API typically rejects further requests until the time window resets. This usually comes as an HTTP 429 "Too Many Requests" response, often with headers indicating how many requests remain or when the client can try again.

Developers work within rate limits by spreading out requests, caching responses, batching calls where possible, and using retry strategies like exponential backoff when a limit is hit.
