An API rate limit is a cap on how many requests a client can send to an API within a set period of time. For example, a service might allow 100 requests per minute or 10,000 requests per day from a single API key. Rate limits exist to protect the server from being overwhelmed, to keep service fair for all users, and to control costs. When a client exceeds its limit, the API typically rejects further requests with an error, often HTTP status code 429 ("Too Many Requests"), until the window resets. Well-designed clients handle this by checking response headers that indicate remaining quota and reset time, and by retrying with exponential backoff.
