An API rate limit is a restriction on how many requests a client can send to an application programming interface (API) within a specific period of time. For example, a service might allow 100 requests per minute from a single API key. Once that threshold is reached, further requests are typically rejected until the time window resets, often with an HTTP 429 "Too Many Requests" status code.

Providers use rate limits to protect their servers from overload, ensure fair access among users, control costs, and prevent abuse such as denial-of-service attacks or scraping. Limits may be applied per user, per API key, per IP address, or per endpoint, and they are often documented alongside the API so developers can design their applications to stay within them. Well-behaved clients handle limits by tracking their request counts, spacing out calls, caching results, and retrying with exponential backoff when a limit is hit.
