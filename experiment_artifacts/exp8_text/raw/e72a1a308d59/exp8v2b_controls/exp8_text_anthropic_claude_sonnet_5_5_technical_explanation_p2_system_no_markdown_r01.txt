A database index is a separate data structure that helps the database find rows quickly without scanning an entire table. It works much like the index at the back of a book: instead of reading every page to find a topic, you look it up in the index and jump straight to the right page.

Most indexes are built on one or more columns and store the values of those columns in a sorted structure, commonly a B-tree. Each entry points to the location of the corresponding row in the table. When you run a query that filters, joins, or sorts on an indexed column, the database can search the index efficiently, typically in logarithmic time, rather than checking every row.

Indexes come with tradeoffs. They take up additional storage space, and they slow down writes such as inserts, updates, and deletes, because the index must be kept in sync with the table. For this reason, it is best to index columns that are frequently used in search conditions, joins, or sorting, and to avoid adding indexes that are rarely used.

In short, an index speeds up data retrieval at the cost of some extra storage and slower writes.
