An API rate limit is a cap on how many requests a client can send to an API within a set period of time, such as 100 requests per minute or 10,000 per day.

**Why they exist**
- **Stability:** They keep any single user from overwhelming the server and slowing it down for everyone else.
- **Fairness:** They spread capacity evenly across all users.
- **Security:** They make brute-force attacks, scraping, and abuse harder.
- **Cost control:** They help providers manage infrastructure expenses and support tiered pricing plans.

**What happens when you exceed one**
The server typically rejects additional requests and returns an HTTP 429 "Too Many Requests" status code. Many APIs also include headers that show your limit, how many requests you have left, and when the counter resets. Some use a `Retry-After` header to say how long to wait.

**How developers handle them**
- Slow down or queue requests so they stay under the limit.
- Cache responses to avoid repeating identical calls.
- Use exponential backoff, meaning wait progressively longer between retries after a rejection.
- Check the API's documentation for its specific limits and consider a higher-tier plan if the limits are too restrictive.

In short, a rate limit is a traffic control mechanism that keeps an API reliable and fair for all of its users.
