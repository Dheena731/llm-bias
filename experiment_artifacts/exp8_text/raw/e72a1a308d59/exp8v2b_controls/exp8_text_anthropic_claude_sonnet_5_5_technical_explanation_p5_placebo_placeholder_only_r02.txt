An API rate limit is a cap on how many requests a client can send to an API within a set period of time, such as 100 requests per minute or 10,000 per day.

**Why they exist**
- **Stability:** They prevent any single user from overwhelming the server and slowing it down for everyone else.
- **Security:** They make it harder to carry out brute-force attacks, scraping, or denial-of-service attempts.
- **Fairness and cost control:** They distribute resources evenly and let providers offer different usage tiers, such as free versus paid plans.

**How they work**
The server tracks how many requests a client (identified by an API key, user account, or IP address) has made during the current time window. Once the limit is reached, further requests are rejected until the window resets. The server typically responds with an HTTP 429 "Too Many Requests" status, and it often includes headers indicating how many requests remain or how long to wait before trying again, such as `Retry-After`.

**How developers handle them**
- Check the rate limit headers and slow down before hitting the cap.
- Retry failed requests with exponential backoff, which means waiting progressively longer between attempts.
- Cache responses so repeated data doesn't require new requests.
- Batch requests where the API allows it.

In short, rate limits keep an API reliable and fair by controlling how often it can be called.
