An API rate limit is a restriction on how many requests a client can make to an API within a specified time period, such as 100 requests per minute or 10,000 per day. Providers set rate limits to protect their servers from overload, ensure fair usage across all users, control costs, and reduce the risk of abuse such as denial-of-service attacks or scraping.

When a client exceeds its limit, the API typically rejects further requests, often returning an HTTP 429 "Too Many Requests" status code, sometimes along with a header indicating when the client can try again. Developers usually handle rate limits by tracking their request volume, spacing out calls, caching responses, and retrying with exponential backoff after a rejection.
