## Background

A database index is a structure, almost always written as a table, that stores values. It serves to speed up searches on those values. The most common use of indexes is for searching, but other applications include sorting, and occasionally grouping.

The most common database indexing techniques are:

1. **Primary key**: A single value that uniquely identifies every single item in the database.
2. **Foreign key**: A value that is a subset of a single value in a separate table, used to link records in two tables. For example, you might have a table of all the users on your site, and a table of their favorite products. You might want to be able to search for all users who like a particular product, but you don't want to have to scan the entire table of all users, because it's too big. Instead, you could link each user to the product they like, and then search for all products that have at least one user linked to them.
3. **Clustered index**: An index that associates a column or set of columns with the row that contains the value in that column.
4. **Sparse column / sparse row**: A sparse column is a column that contains a lot of NULLs, and a sparse row is a row that contains a lot of NULLs. A sparse index is an index that has the sparseness feature built in.

## Searching an Index

Searching an index is very different from searching a normal table. In a normal table, you would scan the whole thing, looking for the values you want. In an index, you can only look for values that are near the values you want. To do this, you need to understand how indexes work.

An index is a table, but it doesn't have a primary key. Each row has at least one column, and that column is the part of the index's definition that tells you what table it comes from.
