Why do we need caching?

Caching helps us save time by reducing the amount of information we have to send to our users. Using a cache means that only the changes that have been made to a website since the cache was last used will be sent to the user. In this way, caching is like a virtual cache drive on a PC.

For example, the article you are currently reading, has not been changed since you read it. We could cache this page and it will remain exactly the same, regardless of when the cache is used. It will be much faster for the user for the information to be sent quickly from the cache than to have to download the whole page and then send it. This is why cached pages are often the first page a website loads for a new visitor.

The other main advantage of caching is that this process is fully automated by the web server. For example, when we set up a site, we can configure it so that the server automatically sends cached pages to users when the information in the page has not been changed, or when it is not appropriate for the user to receive the cached page (if the page is static, meaning that the information is not an evolving one). This means that every time the page is updated, the server automatically sends a small update to the cache. This is then sent to the user, so the page can be updated without having to update the cache manually, and without the inefficiency of sending the entire page. This means that a site with a high number of users will be updated more quickly than one with a small number of users.

It is also important to note that caching does not require that the whole server must be running continuously. The page can be updated every second, but if the server is not running, then the page will not be updated, and the visitor will receive the cached page. On the other hand, it is possible to have a server that never updates the page because the server is running continuously, but if the server stops for any reason, then that page will not be updated either, and the visitor will receive the cached page. The server can even be run by a desktop application, such as a web server that you can download and run on your own computer or server. The user will then enter all the information and the server will send the user the page that is cached, which means that the user does not have to wait for the server to update its page, and the user's machine can go in and out of service without affecting the user experience.
