An API rate limit is a cap on how many requests a client can send to an API within a set period of time, such as 100 requests per minute or 10,000 per day. The provider of the API sets this limit to protect its servers from being overwhelmed, to keep service fair and stable for all users, and sometimes to control costs or encourage customers to move to a paid tier.

When a client goes over the limit, the API usually refuses the extra requests and returns an error, most commonly an HTTP 429 status code meaning "Too Many Requests." Many APIs also include headers in their responses that tell you how many requests you have left and when the limit will reset, or a Retry-After value indicating how long to wait before trying again.

Limits can be applied in different ways. Some are tied to an API key or user account, others to an IP address, and some to specific endpoints that are more expensive to run. Providers also use different counting methods, such as fixed windows that reset at regular intervals, sliding windows that look at the most recent stretch of time, or token buckets that allow short bursts while enforcing an average rate.

To work well within rate limits, developers commonly cache responses, batch requests when possible, spread calls out over time, and use exponential backoff, which means waiting progressively longer between retries after receiving a rate limit error. Reading the API documentation to understand the specific limits is the best way to avoid disruptions.
