An API rate limit is a restriction on how many requests a client can send to an API within a specific time period, such as 100 requests per minute or 10,000 per day. Providers use rate limits to protect their servers from overload, ensure fair access among users, control costs, and prevent abuse such as denial-of-service attacks or scraping. When a client exceeds its limit, the API typically rejects further requests with an error, often HTTP status code 429 ("Too Many Requests"), until the time window resets. Clients often handle this by slowing down requests, retrying after a delay, or caching responses.
