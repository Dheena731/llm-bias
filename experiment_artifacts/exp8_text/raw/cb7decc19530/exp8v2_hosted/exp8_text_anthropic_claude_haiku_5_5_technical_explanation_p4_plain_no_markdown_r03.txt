Caching speeds up a website by storing copies of data or pages so they do not have to be built or fetched again each time someone asks for them. When a visitor first requests a page, the server must do the work: it queries the database, runs application code, assembles the HTML, and sends it back. That process takes time. A cache keeps the result of that work somewhere faster to reach, so later requests for the same content can be answered from the stored copy instead. Caches exist at several points along the way. A browser can keep images and stylesheets locally, a content delivery network can hold copies on servers geographically close to the visitor, and the server itself can store rendered pages or frequently used database results in memory. Because a nearby copy travels a shorter distance and skips expensive computation, the page appears to load much faster, and the server is freed up to handle more visitors at once. Caches must be refreshed or expired when the underlying content changes, so that visitors do not see outdated information, but when managed well they dramatically reduce wait times and server load.
