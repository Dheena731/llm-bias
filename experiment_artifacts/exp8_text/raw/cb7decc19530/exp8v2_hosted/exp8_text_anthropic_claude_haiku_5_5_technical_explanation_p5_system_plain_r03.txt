An API rate limit is a restriction on how many requests a client can send to an application programming interface within a given period of time. For example, a service might allow each user or API key to make 100 requests per minute, or 10,000 requests per day. Once that threshold is reached, further requests are typically rejected until the window resets, often with an error response such as HTTP status code 429, which means "too many requests."

Providers use rate limits for several reasons. They protect servers from being overwhelmed by a single client, whether through a bug, a runaway script, or deliberate abuse. They also help keep service fair for all users, prevent sudden spikes in infrastructure costs, and support tiered pricing, where paying customers receive higher limits. Developers who build on an API usually need to account for rate limits by checking the documentation, caching responses where possible, and retrying failed requests with exponential backoff, which means waiting progressively longer between attempts.
