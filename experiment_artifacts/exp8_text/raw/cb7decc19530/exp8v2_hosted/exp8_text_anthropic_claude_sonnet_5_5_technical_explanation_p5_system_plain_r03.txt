An API rate limit is a cap on how many requests a client can send to an API within a set period of time, such as 100 requests per minute or 10,000 per day. The provider of the API sets this limit and enforces it automatically, usually by tracking requests against an API key, a user account, or an IP address.

Rate limits exist for several reasons. They protect servers from being overwhelmed by a sudden flood of traffic, whether it comes from a bug in a client program, an abusive user, or a deliberate attack. They also help distribute capacity fairly among all users, and they let providers offer different service tiers, with higher limits for paying customers.

When a client exceeds its limit, the API typically rejects further requests until the time window resets. The most common response is an HTTP 429 status code, meaning too many requests. Many APIs also include headers in their responses that tell the client how many requests remain and when the limit will reset, and some include a Retry-After value indicating how long to wait.

Developers working with rate-limited APIs usually handle this by spacing out requests, caching results to avoid repeat calls, batching operations where possible, and using retry logic with exponential backoff, which means waiting progressively longer between attempts after a failure. Reading the provider's documentation is important, since the exact limits and the way they are measured vary from one API to another.
