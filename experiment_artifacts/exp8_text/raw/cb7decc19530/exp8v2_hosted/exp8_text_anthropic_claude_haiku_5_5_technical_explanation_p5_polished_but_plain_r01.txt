An API rate limit is a restriction that controls how many requests a client, such as an application or a user, can send to an application programming interface within a set period of time. For example, a service might allow 100 requests per minute from a single API key. Once that threshold is reached, further requests are typically rejected until the window resets, often with an error response such as HTTP status code 429, which signals "too many requests."

Providers use rate limits for several reasons. They protect servers from being overwhelmed by a single heavy user, which keeps the service responsive for everyone. They help manage infrastructure costs, since every request consumes computing resources. They also discourage abuse, such as scraping large amounts of data or attempting brute-force attacks. Limits may be applied per user, per IP address, per API key, or per endpoint, and they may vary by subscription tier, with paid plans often allowing higher volumes.

For developers, respecting rate limits is an important part of building reliable software. Well-designed clients watch for limit-related responses, slow down when they approach a threshold, and retry after a delay, commonly using exponential backoff, which progressively increases the wait between attempts. Many APIs include headers in their responses that report how many requests remain and when the limit will reset, making it easier to plan request pacing.
