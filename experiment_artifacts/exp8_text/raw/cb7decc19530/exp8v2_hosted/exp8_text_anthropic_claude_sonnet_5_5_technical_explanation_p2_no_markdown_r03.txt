A database index is a separate data structure that helps the database find rows in a table much faster, without having to scan every row. It works much like the index at the back of a book: instead of reading every page to find a topic, you look it up in an alphabetical list that points you straight to the right page.

When you create an index on one or more columns, the database stores the values from those columns in a sorted structure, commonly a B-tree, along with pointers to the full rows. When you run a query that filters or sorts on an indexed column, the database can search this structure quickly, often in logarithmic time, rather than checking every row in the table.

Indexes come with trade-offs. They take up additional storage space, and they slow down writes such as inserts, updates, and deletes, because the index must be updated along with the table. For this reason, it is best to index columns that are frequently used in searches, joins, or sorting, and to avoid adding indexes that are rarely used.
