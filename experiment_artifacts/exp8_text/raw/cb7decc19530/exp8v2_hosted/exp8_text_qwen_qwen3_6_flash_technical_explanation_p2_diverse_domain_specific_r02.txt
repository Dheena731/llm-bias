A database index is a specialized data structure that decouples row location metadata from the base table, enabling efficient random access without full sequential scans. By maintaining an ordered mapping of key values to physical row identifiers (such as TIDs or primary keys), indexes allow the query executor to resolve predicates via targeted seeks—typically using B-tree or hash traversals—rather than inspecting every tuple in the heap.

This optimization significantly reduces disk I/O and CPU consumption for read-heavy workloads, particularly for equality checks and range filters. The cost is structural: indexes increase storage footprint and impose write amplification, as every `INSERT`, `UPDATE`, or `DELETE` on indexed columns requires concurrent modifications to the index tree to preserve ordering and consistency.
