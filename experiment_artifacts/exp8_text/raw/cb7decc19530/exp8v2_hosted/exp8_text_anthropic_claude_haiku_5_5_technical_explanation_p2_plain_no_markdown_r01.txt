A database index is a separate data structure that the database maintains alongside a table to speed up searches. Without an index, finding rows that match a condition usually requires a full table scan, where the database reads every row one by one until it has checked them all. An index works like the index at the back of a book: it stores the values of one or more columns in a sorted or otherwise organized form, along with pointers to the rows that contain those values. When a query filters or sorts on an indexed column, the database can consult the index to locate the matching rows directly instead of reading the entire table. The tradeoff is that indexes take up additional storage and must be updated whenever rows are inserted, changed, or deleted, which adds some cost to write operations. Because of this balance, developers typically index columns that are frequently used in lookups, joins, or ordering, while avoiding indexes on columns that are rarely queried.
