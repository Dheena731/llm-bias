An API rate limit is a restriction on how many requests a client can send to an API within a specific time period, such as 100 requests per minute or 10,000 requests per day. Providers set these limits to protect their servers from overload, ensure fair access for all users, control costs, and prevent abuse such as denial-of-service attacks or scraping. When a client exceeds the limit, the API typically rejects further requests, often with an HTTP 429 "Too Many Requests" status code, until the time window resets. Developers usually handle rate limits by checking response headers that indicate remaining quota, and by retrying with exponential backoff.
