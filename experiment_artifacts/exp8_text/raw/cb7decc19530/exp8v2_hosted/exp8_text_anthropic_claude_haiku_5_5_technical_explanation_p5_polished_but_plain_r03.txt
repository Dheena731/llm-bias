An API rate limit is a restriction on how many requests a client can send to an application programming interface within a given period of time. A service might allow, for example, one hundred requests per minute or ten thousand per day from a single API key. Once that threshold is reached, the server typically rejects further requests for the remainder of the window, often responding with an error such as HTTP status code 429, which means "too many requests."

Providers impose rate limits for several reasons. They protect server resources from being overwhelmed by a single user or a runaway script, they help keep performance consistent for everyone sharing the service, and they make usage predictable and fair. Limits also serve as a practical control on costs, since every request consumes computing power and bandwidth, and they can discourage abuse such as scraping or brute-force attacks.

For developers, rate limits shape how software should be built. A well-behaved client tracks its request count, spaces out calls, and handles rejections gracefully, usually by waiting and retrying with exponential backoff rather than hammering the server. Many APIs communicate their limits through response headers that report how many requests remain and when the quota resets, allowing applications to adjust their behavior in real time.
