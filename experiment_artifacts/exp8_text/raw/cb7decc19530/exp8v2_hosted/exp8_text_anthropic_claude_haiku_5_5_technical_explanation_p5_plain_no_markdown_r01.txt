An API rate limit is a restriction that controls how many requests a client can send to an application programming interface within a set period of time. For example, a service might allow a user to make 100 requests per minute or 10,000 requests per day. Once that threshold is reached, further requests are typically rejected until the window resets, often with an error response such as HTTP status code 429, which means "too many requests."

Providers use rate limits for several reasons. They protect servers from being overwhelmed by a single user or a sudden spike in traffic, which helps keep the service stable and responsive for everyone. They also help ensure fair access across many users, prevent abuse such as automated scraping or denial-of-service attempts, and support business models where different customers pay for different usage tiers. Developers who build on an API are expected to design their applications around these limits, commonly by caching results, batching requests, and retrying with increasing delays when they receive a rejection.
