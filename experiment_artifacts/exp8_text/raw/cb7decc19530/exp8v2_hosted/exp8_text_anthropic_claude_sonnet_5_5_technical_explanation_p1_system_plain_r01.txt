Latency is the delay between a user's action and the system's response, and it matters in web applications because people experience that delay directly. When a page takes too long to load or a button seems unresponsive, users notice immediately, and their patience is shorter than many developers expect. Research from large companies has repeatedly shown that even small increases in response time lead to measurable drops in engagement, conversions, and revenue. A delay of a few hundred milliseconds can change how a site feels, making it seem either fluid and trustworthy or sluggish and unreliable.

Latency also compounds. A single page often depends on many requests, such as the initial document, stylesheets, scripts, images, and calls to APIs. Each request pays the cost of network round trips, DNS lookups, connection setup, and server processing time. When these steps happen one after another, small delays add up to a noticeably slow experience. This is why mobile users on weaker or less stable connections are especially affected, since each round trip can take far longer than it does on a fast wired network.

Beyond user perception, latency affects search rankings, since search engines factor page speed into their evaluations, and it influences how interactive features behave. Real-time tools like chat, collaborative editing, and online games depend on quick exchanges, and high latency makes them feel broken rather than merely slow.

Because latency is partly bound by physical limits like the speed of light across long distances, it cannot be solved by raw bandwidth alone. Developers address it by reducing the number of requests, caching content, using content delivery networks to place data closer to users, optimizing server code and database queries, and loading only what is needed first. Treating latency as a core design concern, rather than something to fix later, tends to produce applications that people find pleasant to use and are more likely to return to.
