Caching speeds up a website by storing copies of data or files closer to where they are needed, so that they do not have to be generated or fetched again for every visitor. Without caching, each request might require the server to run database queries, assemble a page from templates, and then send every image, stylesheet, and script across the network from the origin server. This work takes time, and under heavy traffic it can strain the server as well. With caching, a previously computed result is saved and reused for subsequent requests, which shortens the path a request must travel and reduces the amount of processing involved.

Caching happens at several layers. A browser cache keeps static assets such as logos, CSS files, and JavaScript on the visitor's own device, so returning visitors do not need to download them again. A content delivery network stores copies of files on servers distributed around the world, so a user in Tokyo can receive content from a nearby node rather than from a server in another continent. On the server itself, application caches can hold the results of expensive database queries or fully rendered pages, so that the next identical request is answered almost instantly without repeating the work.

The overall effect is faster page loads, lower bandwidth and server costs, and a site that remains responsive when many people visit at once. Good caching depends on setting appropriate expiration times and invalidation rules, so visitors see fresh content when it matters while still benefiting from the speed that reuse provides.
