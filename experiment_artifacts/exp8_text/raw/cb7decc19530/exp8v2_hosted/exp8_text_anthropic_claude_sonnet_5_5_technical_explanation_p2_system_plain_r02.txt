A database index is a separate data structure that helps the database find rows quickly without scanning an entire table. Without an index, a query that looks for a particular value, such as a customer with a specific email address, has to read every row and check each one. With an index on the email column, the database can jump almost directly to the matching rows, much as you would use the index at the back of a book to find a topic instead of reading every page.

Most indexes are built as a balanced tree, which keeps the values in sorted order and lets the database narrow down its search in a few steps even when the table holds millions of rows. Some systems also offer other types, such as hash indexes, which are fast for exact matches but not for ranges. Because the values are kept in order, an index can also speed up sorting, range queries like finding all orders between two dates, and joins between tables.

Indexes come with tradeoffs. They take up additional storage, and every time a row is inserted, updated, or deleted, the database must also update the relevant indexes, which makes writes somewhat slower. For this reason, it is usually best to index the columns that are searched, joined, or sorted often, rather than adding indexes everywhere.
