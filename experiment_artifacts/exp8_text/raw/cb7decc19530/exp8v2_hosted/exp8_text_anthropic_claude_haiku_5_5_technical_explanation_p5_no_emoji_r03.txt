An API rate limit is a restriction on how many requests a client can send to an application programming interface (API) within a specific time period, such as 100 requests per minute or 10,000 requests per day. Providers set these limits to protect their servers from overload, ensure fair access among many users, control costs, and prevent abuse such as denial-of-service attacks or scraping. When a client exceeds its limit, the API typically rejects further requests, often with an HTTP 429 "Too Many Requests" status code, until the time window resets. Developers commonly handle rate limits by checking response headers that indicate remaining quota, retrying after a delay, and using techniques like exponential backoff.
