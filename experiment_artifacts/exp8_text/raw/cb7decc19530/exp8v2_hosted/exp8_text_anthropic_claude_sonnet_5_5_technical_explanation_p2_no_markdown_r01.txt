A database index is a separate data structure that helps the database find rows quickly without scanning an entire table. It works much like the index at the back of a book: instead of reading every page to find a topic, you look it up in the index and jump straight to the right page.

Most indexes are built on one or more columns and are usually stored as a balanced tree, which keeps the values in sorted order. When you run a query that filters, sorts, or joins on an indexed column, the database can search this structure in a small number of steps rather than checking every row. For large tables, this can reduce query times from seconds to milliseconds.

Indexes come with tradeoffs. They take up additional storage space, and they must be updated whenever data is inserted, changed, or deleted, which can slow down write operations. For this reason, it is best to index columns that are frequently searched or joined on, and to avoid adding indexes that are rarely used.
