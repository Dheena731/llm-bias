An API rate limit is a restriction on how many requests a client can send to an application programming interface (API) within a specific period of time. For example, a service might allow 100 requests per minute or 10,000 requests per day from a single user or API key. Rate limits protect servers from being overwhelmed, help keep service fair for all users, prevent abuse such as scraping or denial-of-service attempts, and control infrastructure costs. When a client exceeds its limit, the API typically rejects further requests for a period of time, often returning an HTTP 429 "Too Many Requests" status code. Developers usually handle this by slowing down their requests, caching responses, or retrying after a delay.
