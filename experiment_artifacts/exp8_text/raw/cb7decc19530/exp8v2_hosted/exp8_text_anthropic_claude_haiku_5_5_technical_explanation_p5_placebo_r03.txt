An API rate limit is a cap on how many requests a client, such as an app or a user, can send to an application programming interface (API) within a set period of time. For example, a service might allow 100 requests per minute per API key. When a client exceeds that cap, the server typically rejects further requests for a while, often returning an HTTP 429 "Too Many Requests" status code.

Providers use rate limits to keep their servers stable, to prevent abuse such as scraping or denial-of-service attempts, and to distribute capacity fairly among many users. For developers, the practical consequence is that code calling an API should track its request volume, handle 429 responses gracefully (commonly by waiting and retrying), and avoid sending bursts of requests that exceed the allowed rate.
