An API rate limit is a restriction on how many requests a client can send to an application programming interface within a specific period of time. For example, a service might allow 100 requests per minute or 10,000 requests per day from a single API key or IP address. Rate limits exist to protect servers from being overwhelmed, to ensure fair access for all users, to control costs, and to prevent abuse such as denial-of-service attacks or scraping. When a client exceeds its limit, the API typically rejects further requests for a period of time, often returning an error such as HTTP status code 429 (Too Many Requests). Developers usually handle rate limits by slowing down request rates, caching responses, batching requests, or retrying after a delay, often using an exponential backoff strategy.
