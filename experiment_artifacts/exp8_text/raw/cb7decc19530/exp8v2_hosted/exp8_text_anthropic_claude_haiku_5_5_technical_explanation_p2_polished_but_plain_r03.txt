A database index is a supporting data structure that helps the database find rows quickly without scanning an entire table. Much like the index at the back of a book, which points a reader to the pages where a topic appears, a database index maps the values in one or more columns to the locations of the rows that contain them. When a query filters or sorts on an indexed column, the database engine can consult the index to jump directly to the matching records instead of reading every row in sequence.

Most indexes are built as balanced tree structures, commonly B-trees, which keep values in sorted order and allow lookups, range searches, and ordering operations to complete in a number of steps that grows slowly with the size of the table. The benefit can be dramatic: a query that once required reading millions of rows may finish after examining only a handful of index entries.

Indexes are not free, however. Each one consumes additional storage, and every insert, update, or delete must also modify the index so that it stays accurate. For this reason, good database design involves choosing indexes deliberately, typically on columns that appear frequently in search conditions, join criteria, or sorting clauses, rather than indexing everything.
