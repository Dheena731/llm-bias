An API rate limit is a restriction that controls how many requests a client can send to an application programming interface within a set period of time. For example, a service might allow a user to make 100 requests per minute or 10,000 requests per day. Once that threshold is reached, the server typically rejects further requests for a while, often returning an error such as HTTP status code 429, which means "too many requests."

Providers impose rate limits for several reasons. They protect servers from being overwhelmed by excessive traffic, which could otherwise slow down or crash the service for everyone. They also ensure fair usage among many customers sharing the same infrastructure, and they can help manage costs or enforce different tiers of service, such as free and paid plans. Developers building applications that rely on an API generally need to design their code to respect these limits, for instance by caching responses, batching requests, or retrying after a delay with exponential backoff.
