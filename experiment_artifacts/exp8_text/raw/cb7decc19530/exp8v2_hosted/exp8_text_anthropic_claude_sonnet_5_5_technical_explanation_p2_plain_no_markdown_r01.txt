A database index is a separate data structure that helps the database find rows quickly without scanning an entire table. Without an index, a query that filters on a particular column has to examine every row to see which ones match, which becomes slow as the table grows. With an index on that column, the database can jump almost directly to the matching rows, much as a reader uses the index at the back of a book to find a topic instead of reading every page.

Most indexes are built using a balanced tree structure, which keeps the values in sorted order and lets the database narrow down its search in a small number of steps, even across millions of rows. Because the values are sorted, indexes also speed up range queries and sorting, such as finding all orders placed between two dates or returning results in alphabetical order.

Indexes come with tradeoffs. They take up additional storage space, and they must be updated whenever rows are inserted, changed, or deleted, which makes writes somewhat slower. For this reason, it is best to create indexes on columns that are queried often and to avoid adding them everywhere. A well-chosen set of indexes can make a database dramatically faster for reading, while too many can burden it with unnecessary overhead.
