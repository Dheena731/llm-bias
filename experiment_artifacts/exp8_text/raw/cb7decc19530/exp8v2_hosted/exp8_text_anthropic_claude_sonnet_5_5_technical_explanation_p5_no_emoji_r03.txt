An API rate limit is a cap on how many requests a client can make to an API within a set period of time, such as 100 requests per minute or 10,000 per day.

Providers use rate limits for several reasons:

- **Stability:** They prevent any single user from overloading the servers and slowing the service for everyone else.
- **Fair usage:** They distribute resources evenly among all clients.
- **Security:** They make abuse harder, including brute-force login attempts, scraping, and denial-of-service attacks.
- **Cost control:** They help providers manage infrastructure costs, and they often serve as a basis for pricing tiers.

When a client exceeds the limit, the API typically rejects further requests and returns an HTTP 429 "Too Many Requests" status code. The response often includes headers, such as `Retry-After`, that indicate when the client can try again.

To work within rate limits, developers commonly cache responses, batch requests, and use exponential backoff, which means waiting progressively longer between retries after a failure.
