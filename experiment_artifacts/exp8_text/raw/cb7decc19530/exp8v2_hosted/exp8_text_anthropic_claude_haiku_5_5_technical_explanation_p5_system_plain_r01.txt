An API rate limit is a restriction on how many requests a client can make to an application programming interface within a given period of time. For example, a service might allow a developer's application to send 100 requests per minute or 10,000 requests per day. Once that threshold is reached, the server typically rejects further requests for the remainder of the window, often responding with an error such as HTTP status code 429, which means "too many requests."

Providers use rate limits for several reasons. They protect servers from being overwhelmed by a single user or a sudden spike in traffic, they help ensure fair access so that one heavy consumer does not degrade service for everyone else, and they can serve as a business tool for managing usage tiers, where paying customers receive higher limits. Developers working with APIs usually handle rate limits by checking response headers that report remaining quota, slowing down their request rate, caching results to avoid repeated calls, or retrying failed requests after a waiting period, often with exponential backoff.
