An API rate limit is a cap on how many requests a user, application, or IP address can send to an API within a set period of time, such as 100 requests per minute or 10,000 per day. Providers put these limits in place to protect their servers from being overwhelmed, to keep service fair and available for all users, to prevent abuse or attacks, and to control costs.

When a client goes over the limit, the API usually rejects further requests for a while and returns an error, most commonly HTTP status code 429 (Too Many Requests). Many APIs also include headers in their responses that show how many requests remain and when the limit will reset.

To work within rate limits, developers often cache responses, batch requests when possible, spread calls out over time, and use retry logic with exponential backoff, which means waiting progressively longer between retries after hitting the limit.
