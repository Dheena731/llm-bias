An API rate limit is a cap on how many requests a user, application, or IP address can send to an API within a specific period of time, such as 100 requests per minute or 10,000 requests per day.

Providers set rate limits for a few main reasons. They protect servers from being overwhelmed by too much traffic, they keep service fair so no single user consumes all the resources, they help prevent abuse such as scraping or denial-of-service attacks, and they allow providers to manage costs and offer different pricing tiers.

When a client exceeds the limit, the API usually rejects further requests until the time window resets. This typically comes back as an HTTP 429 "Too Many Requests" error, often with a header like Retry-After that says how long to wait.

Developers can work within rate limits by caching responses, batching requests, spacing calls out, and using exponential backoff, which means waiting progressively longer between retries after a failure.
