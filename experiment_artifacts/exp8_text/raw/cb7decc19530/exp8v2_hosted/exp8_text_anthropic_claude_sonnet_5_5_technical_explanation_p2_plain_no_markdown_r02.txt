A database index is a separate data structure that helps the database find rows quickly without scanning an entire table. Without an index, a query that looks for a particular value, such as a customer with a given email address, has to read every row and check each one. That works fine for small tables but becomes slow as the data grows into the millions of rows.

An index works much like the index at the back of a book. Instead of flipping through every page to find a topic, you look it up in an ordered list that tells you exactly where to go. In most databases, an index is stored as a balanced tree, which keeps the values sorted and lets the system narrow down the location of a match in just a few steps. Some databases also offer other types, such as hash indexes, which are fast for exact matches but not for ranges.

Indexes speed up lookups, sorting, and joins between tables, but they come with costs. They take up additional storage space, and every time a row is inserted, updated, or deleted, the database must also update the relevant indexes. This makes writes somewhat slower. Because of this tradeoff, indexes are usually created on the columns that are searched or joined most often, rather than on every column in a table.
