An API rate limit is a restriction on how many requests a client can make to an application programming interface within a given period of time. For example, a service might allow a developer's application to send 100 requests per minute or 10,000 requests per day. Once the limit is reached, further requests are typically rejected with an error response, often with an HTTP status code of 429 (Too Many Requests), until the time window resets.

Providers use rate limits for several reasons. They protect servers from being overwhelmed by a single user or a sudden spike in traffic, they keep the service fair and responsive for all users, and they help control costs and enforce usage agreements or pricing tiers. Limits may apply per API key, per user account, per IP address, or per endpoint, and they are often documented so developers can design their applications to stay within them. Well-behaved clients handle rate limits by spacing out requests, caching results, or retrying after a delay, commonly using an exponential backoff strategy.
