An API rate limit is a cap on how many requests a client can send to an application programming interface within a given period of time. Providers impose these limits to protect their servers from being overwhelmed, to ensure that resources are shared fairly among many users, and to control costs or enforce usage tiers. A limit might allow, for example, one hundred requests per minute or ten thousand per day. When a client exceeds the allowed quota, the server typically rejects further requests for a while, often returning an error such as HTTP status 429, which means "too many requests." Well-designed APIs often include headers that tell the client how many requests remain and when the window resets, allowing software to slow down or retry at the right moment. Developers who build against an API are generally expected to respect its rate limits by caching results, batching operations, and using exponential backoff when retrying failed calls.
