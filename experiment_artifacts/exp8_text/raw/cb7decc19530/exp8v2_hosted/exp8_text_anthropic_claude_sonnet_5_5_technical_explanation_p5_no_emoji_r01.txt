An API rate limit is a cap on how many requests a client can make to an API within a set period of time, such as 100 requests per minute or 10,000 per day.

Providers use rate limits for several reasons:

- **Stability:** They prevent any single user from overwhelming the server and degrading service for others.
- **Fairness:** They distribute capacity evenly among all users.
- **Security:** They make abuse, such as brute-force attacks or scraping, harder.
- **Cost control:** They help providers manage infrastructure costs and support tiered pricing plans.

When a client exceeds the limit, the API typically rejects further requests and returns an error, most commonly HTTP status code 429 ("Too Many Requests"). The response often includes headers, such as `Retry-After`, that indicate when the client can try again.

Developers usually handle rate limits by spacing out requests, caching responses, batching calls, or retrying with exponential backoff, which means waiting progressively longer between each retry.
