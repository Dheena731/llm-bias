An API rate limit is a cap on how many requests a client can send to an API within a set period of time, such as 100 requests per minute or 10,000 requests per day. (An API is the interface that lets one piece of software request data or actions from another.)

**Why they exist**
- **Protecting the service:** Limits keep a server from being overwhelmed by too much traffic, whether accidental or malicious.
- **Fair use:** They prevent one user from consuming resources that others need.
- **Cost control and pricing:** Providers often offer higher limits on paid plans.

**What happens when you exceed the limit**
The API typically rejects additional requests until the time window resets. Many APIs do this by returning an HTTP status code 429 ("Too Many Requests"). Some also include information in the response, such as how long to wait before trying again or how many requests remain, though the exact details vary by provider.

**How to work with rate limits**
- Check the API's documentation for its specific limits.
- Slow down or space out your requests.
- Cache responses you have already received, so you don't request the same data repeatedly.
- If you receive a rate-limit error, wait before retrying, and increase the wait after each repeated failure.

In short, a rate limit is a rule set by the API provider that controls how frequently you can make requests, so the service stays stable and available for everyone.
