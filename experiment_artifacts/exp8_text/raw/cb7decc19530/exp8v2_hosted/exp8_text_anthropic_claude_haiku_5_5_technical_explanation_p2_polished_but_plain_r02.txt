A database index is a supporting data structure that helps the database find rows quickly without scanning an entire table. Much like the index at the back of a book, which lets a reader jump straight to the page on a given topic rather than reading every page, a database index stores a sorted or organized copy of the values in one or more columns, along with pointers to the rows that contain them. When a query filters or sorts on an indexed column, the database can search this smaller, ordered structure to locate matching rows directly, which often reduces the work from examining millions of records to examining only a handful.

Indexes trade space and write performance for read speed. Each index consumes additional storage, and every insert, update, or delete must also update the index, so heavily indexed tables can slow down data modification. For this reason, indexes are usually created on columns that appear frequently in search conditions, join criteria, or ordering clauses, rather than on every column. Choosing the right indexes requires balancing the needs of common queries against the cost of maintaining them.
