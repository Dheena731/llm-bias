Caching accelerates web delivery by intercepting repeated requests before they reach the origin server. On initial page load, the browser stores static assets and cacheable API responses locally, using HTTP directives like `Cache-Control: max-age` or `ETag` validations to decide whether to reuse them on subsequent visits. At the infrastructure layer, reverse proxies (Nginx, Varnish) and CDNs hold rendered fragments and static files at edge locations. When a user requests a cached response, the edge node serves it directly, skipping TLS handshakes, backend template rendering, and database joins. Only requests that miss the cache window—typically personalized pages, POST payloads, or stale entries past their TTL—propagate back to the origin. This layered approach compresses Time to First Byte, drops unnecessary egress bandwidth, and keeps response times consistent during traffic spikes because the origin processes only genuine misses.
