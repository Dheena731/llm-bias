An API rate limit is a cap on how many requests a client can send to an API within a set period of time. For example, a service might allow 100 requests per minute for each user or each access key. Once that threshold is reached, the API typically refuses further requests until the time window resets, often returning an HTTP 429 status code that means "Too Many Requests."

Providers set rate limits for several reasons. They protect servers from being overwhelmed by sudden spikes in traffic, whether accidental or malicious. They keep service fair, so that one heavy user cannot degrade performance for everyone else. They also help providers control infrastructure costs and enforce different service tiers, with higher limits offered to paying customers.

Limits can be defined in different ways. Some are based on a fixed window, such as a count that resets every minute, while others use a sliding window or a token bucket that refills gradually. Limits may apply per user, per IP address, per application, or per endpoint, and expensive operations are sometimes restricted more tightly than simple ones.

For developers, the practical concern is to build applications that respond gracefully. Many APIs include headers in their responses that report the allowed quota, how much remains, and when it resets, and a well-written client reads these values. When a limit is hit, the client should pause and retry after the indicated delay, ideally using exponential backoff, which means waiting progressively longer between attempts. Caching responses, batching requests, and avoiding unnecessary calls can also keep usage comfortably within the limit.
