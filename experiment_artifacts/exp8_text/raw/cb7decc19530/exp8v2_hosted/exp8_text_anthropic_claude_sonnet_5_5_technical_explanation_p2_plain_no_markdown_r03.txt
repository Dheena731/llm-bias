A database index is a separate data structure that lets the database find rows quickly without scanning an entire table. Without an index, a query that looks for a particular value, such as a customer with a given email address, has to read every row and check each one. That works fine for small tables but becomes slow as they grow to millions of records.

An index works much like the index at the back of a book. It stores the values from one or more columns in a sorted arrangement, usually a balanced tree, along with pointers to the rows where those values live. Because the entries are sorted, the database can jump to the right spot in a handful of steps instead of examining everything. This also makes range queries and sorted results faster, since related values sit next to each other.

The tradeoff is cost. An index takes up additional storage, and every time a row is inserted, updated, or deleted, the database must also update the indexes that involve the affected columns. Too many indexes can therefore slow down writes and waste space. In practice, people create indexes on columns that are searched, joined, or sorted often, and avoid them on columns that are rarely queried or that change constantly.
