A database index is a separate data structure that helps the database find rows quickly without scanning an entire table. It works much like the index at the back of a book: instead of reading every page to find a topic, you look it up in an organized list that points you straight to the right location.

When you create an index on a column, such as a customer's email address, the database stores the values from that column in a sorted structure, most commonly a balanced tree, along with references to the rows that contain them. When a query filters or joins on that column, the database can search the structure in a handful of steps rather than examining every row. On a table with millions of records, this can turn a query that takes seconds into one that takes milliseconds. Indexes also help with sorting and with enforcing uniqueness, since the data is already arranged in order.

The benefit comes with costs. An index takes up storage space, and every time a row is inserted, updated, or deleted, the database must also update any indexes affected by that change. This makes writes somewhat slower, and a table with too many indexes can become sluggish to modify. Indexes are also only useful when a query can take advantage of them. A column with very few distinct values, such as a yes or no flag, often gains little from indexing, and queries that apply functions to a column or retrieve most of the table may ignore the index entirely.

In practice, the best approach is to index the columns that appear frequently in search conditions, joins, and sort operations, then check how the database actually executes your queries and adjust from there. A well-chosen set of indexes is one of the most effective ways to improve database performance.
