A database index is a supplemental data structure that maps column values to row identifiers, enabling the query engine to locate matching records without scanning the full table. Typically built as a balanced tree or hash table, it stores sorted keys alongside pointers to physical disk pages or heap slots. When a query contains a filter, join predicate, or ordering clause, the optimizer can traverse the index to perform targeted lookups instead of a sequential scan, dramatically cutting I/O and comparison cycles. The trade-off is structural: every `INSERT`, `UPDATE`, or `DELETE` must also mutate the index, adding write latency and consuming additional storage. Indexes do not alter how data is persisted; they maintain a navigational overlay that only yields performance gains when the workload’s access patterns match the indexed columns’ cardinality and distribution.
