An API rate limit is a restriction that controls how many requests a client can make to an application programming interface (API) within a specific period of time. For example, a service might allow 100 requests per minute or 10,000 requests per day from a single user, API key, or IP address. Once that limit is reached, further requests are typically rejected until the time window resets, often with an error response such as HTTP status code 429 (Too Many Requests).

Providers use rate limits to protect their servers from overload, ensure fair access among many users, prevent abuse such as scraping or denial-of-service attacks, and manage costs. Developers working with APIs usually need to design their applications to respect these limits, for example by caching results, batching requests, or retrying with exponential backoff when a limit is hit.
