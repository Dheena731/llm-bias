A database index is a separate data structure that helps the database find rows in a table without scanning every one of them. It works much like the index at the back of a book: instead of reading every page to find a topic, you look it up in an organized list that tells you exactly where to go.

Most indexes are built on a structure such as a B-tree, which keeps the values of one or more columns in sorted order along with pointers to the rows that contain them. Because the values are sorted and organized in a balanced tree, the database can locate a specific value in a handful of steps, even in a table with millions of rows. This makes lookups, range queries, and sorting by the indexed column much faster, and it also speeds up joins that match on indexed columns.

Indexes come with tradeoffs. They take up additional storage, and every time you insert, update, or delete a row, the database must also update the relevant indexes, which slows down writes. For this reason, it usually makes sense to index columns that are frequently searched, filtered, or joined on, and to avoid adding indexes that are rarely used. A well-chosen set of indexes can turn a slow query into a nearly instant one, while too many can burden the system with unnecessary overhead.
