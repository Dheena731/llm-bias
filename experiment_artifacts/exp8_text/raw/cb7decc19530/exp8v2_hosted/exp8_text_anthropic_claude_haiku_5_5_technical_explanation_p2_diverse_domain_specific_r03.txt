An index is a separate, sorted structure the database keeps alongside a table so it can find rows without reading the whole table. Say you have a `shipments` table with 40 million rows and you run `WHERE tracking_number = ' 1Z999AA10123456784'` often. Without an index, the engine scans every row until it finds a match. With an index on `tracking_number`, it walks a B-tree of sorted keys, usually three or four page reads, and jumps straight to the row's location on disk.

The cost is that every insert, update, or delete also has to update each index on the table. A write-heavy table with six indexes does six extra tree modifications per row, and each index takes its own disk space. So you index the columns your queries filter, join, or sort on, and you skip the ones nobody searches by. An index nobody uses is pure overhead, and most databases can tell you which ones those are.
