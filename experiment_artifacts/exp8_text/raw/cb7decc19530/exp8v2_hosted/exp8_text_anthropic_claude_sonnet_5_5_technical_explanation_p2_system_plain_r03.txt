A database index is a separate data structure that helps the database find rows in a table without scanning every one of them. It works much like the index at the back of a book. Instead of reading every page to find a topic, you look it up in the index, which tells you exactly where to turn.

When you create an index on a column, the database builds and maintains a sorted structure, commonly a balanced tree, that stores the values from that column along with pointers to the rows that contain them. When you run a query that filters or sorts on that column, the database can use the structure to jump quickly to the matching entries rather than checking each row in turn. For a large table, this can turn a search that takes seconds or minutes into one that takes milliseconds.

Indexes come with tradeoffs. They take up additional storage space, and they must be updated every time you insert, update, or delete rows in the table, which makes writes somewhat slower. Because of this, it is usually best to index the columns that are searched, joined, or sorted on frequently, and to avoid adding indexes that are rarely used. Choosing the right indexes is one of the most effective ways to improve the performance of a database.
