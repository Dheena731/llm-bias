A database index is a separate, sorted structure that the database maintains alongside a table so it can find rows without reading the whole table. Suppose a `orders` table holds 40 million rows and you run `WHERE customer_email = 'dana.ruiz@example.com'`. Without an index, the engine reads every row and checks its email. With an index on `customer_email`, it walks a B-tree, a balanced tree of sorted keys, to the matching entries in a handful of page reads, then fetches those rows.

The cost is that every insert, update, or delete must also update each index on the affected columns, so heavily indexed write-heavy tables get slower. Indexes also take disk space and memory. The query planner decides whether to use one, and it may skip an index if the filter matches a large share of the table, since a sequential scan can be faster than many random lookups.
