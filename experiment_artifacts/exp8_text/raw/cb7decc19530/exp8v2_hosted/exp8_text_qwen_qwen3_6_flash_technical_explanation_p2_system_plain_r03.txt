A database index functions much like the index at the end of a reference book. When a query searches a large table without an index, the database engine must examine every row sequentially until it locates the matching records. An index builds a separate, optimized structure that stores selected column values in a sorted order along with direct references to the physical location of those rows. By consulting this structure first, the database can skip the full table scan and retrieve results almost instantly. Creating an index requires additional disk space and introduces a small overhead during data modifications, since the index must be updated whenever rows are added, changed, or removed. Despite that tradeoff, indexes significantly accelerate read operations, especially for filtering, sorting, and joining large datasets.
