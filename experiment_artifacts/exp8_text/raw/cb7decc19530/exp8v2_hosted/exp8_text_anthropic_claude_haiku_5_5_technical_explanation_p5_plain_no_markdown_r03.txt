An API rate limit is a restriction that a service places on how many requests a client can make to its application programming interface within a given period of time. For example, a provider might allow a developer's application to send 100 requests per minute or 10,000 requests per day. Once that threshold is reached, further requests are typically rejected until the window resets, often with an error response such as HTTP status code 429, which means "too many requests."

Providers use rate limits for several reasons. They protect their servers from being overwhelmed by a single user or a sudden spike in traffic, they help ensure fair access so that one heavy consumer does not degrade the experience for everyone else, and they can serve as a way to manage costs or enforce different service tiers, where paying customers receive higher limits. Developers working with an API are generally expected to design their software to respect these limits, for instance by caching results, batching requests, or pausing and retrying after a delay when a limit is hit.
