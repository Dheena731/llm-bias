A database index is a separate data structure that helps the database find rows quickly without scanning an entire table. Much like the index at the back of a book, which points you to the pages where a topic appears, a database index maps the values in one or more columns to the locations of the rows that contain them. When a query filters or sorts on an indexed column, the database can consult the index to jump directly to the matching rows instead of reading every record in the table.

Indexes are typically built on tree structures or hash tables, which keep the stored values organized so that lookups take a small, predictable number of steps even as the table grows to millions of rows. The benefit is most noticeable for selective queries, where only a small fraction of rows match the condition. The tradeoff is that every insert, update, or delete must also update the index, and the index consumes additional storage. For this reason, good database design involves indexing the columns that are frequently searched or joined on, while avoiding unnecessary indexes that slow down writes without improving reads.
